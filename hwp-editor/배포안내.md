# 실행 파일 만들기와 보안 경고 없애기

원본(`범정부오피스20250819.exe`)과 같은 방식(PyInstaller 한 파일)으로 exe 를 만들고,
윈도우에서 내려받아 실행할 때 뜨는 경고를 없애는 방법을 정리했습니다.

> **먼저 알아둘 것**
> PyInstaller 는 교차 빌드를 지원하지 않아, exe 는 **윈도우에서** 만드는 것이 정석입니다
> (`build_win.bat` 한 번). 윈도우 PC 가 없으면 리눅스에서 **Wine + 윈도우용 CPython** 으로
> 만드는 길도 넣어 두었습니다(`build_wine.sh`). 이때 나오는 것도 진짜 윈도우 실행
> 파일(PE32+)이며, 부트로더까지 PyInstaller 의 윈도우 wheel 에서 나온 것입니다.

---

## 1. exe 만들기

```
1) 압축을 풀고 hwp-editor 폴더로 들어갑니다.
2) build_win.bat 을 두 번 누릅니다.
   (파이썬 3.10 이상 필요 — 없으면 python.org 에서 설치, 설치 때 "Add python.exe to PATH" 켜기)
3) dist\한글문서도우미.exe 가 만들어집니다.
```

`build_win.bat` 이 하는 일: 가상환경 만들기 → 의존성 설치 → **시험 448개 실행** →
PyInstaller 빌드. 시험이 실패하면 빌드를 멈추므로 깨진 exe 가 나오지 않습니다.

### 한 파일 형태 vs 폴더 형태

| | 한 파일 (기본) | 폴더 형태 |
|---|---|---|
| 배포 | exe 하나만 주면 됨 | 폴더 통째로(또는 zip) |
| 시작 속도 | 느림(매번 임시폴더에 풀어서 실행) | 빠름 |
| 백신 오탐 | **더 자주 걸림** | 적음 |
| 만드는 법 | `build_win.bat` | **`build_win_folder.bat`** (두 번 누르면 끝) |

사내 공유 폴더나 업무 PC에 배포한다면 **폴더 형태를 권합니다.** 한 파일 형태는
실행할 때마다 자신을 임시 폴더에 풀기 때문에, 이 동작 자체를 백신이 의심합니다.

### 윈도우 PC 가 없을 때 (리눅스에서 만들기)

```
sudo apt-get install -y --no-install-recommends wine64
bash build_wine.sh                    # → dist_wine/한글문서도우미.exe (한 파일)
HWPKIT_ONEDIR=1 bash build_wine.sh    # → dist_wine/한글문서도우미/ + .zip (폴더 형태)
```

윈도우용 CPython(tkinter 포함)을 내려받아 Wine 위에서 PyInstaller 를 돌립니다.
주의할 점 두 가지를 스크립트에 반영해 두었습니다.

- 변수 이름은 **영문**으로. bash 는 한글 변수 이름을 변수로 보지 않고 명령으로
  실행하려 들어 `command not found` 로 죽습니다.
- 빌드 출력은 파일로 바로 받지 말고 **파이프**로 넘길 것. 파일 핸들을 물려주면
  Wine 의 파이썬이 `init_sys_streams: can't initialize sys standard streams
  (WinError 6)` 로 죽습니다.

## 2. 보안 경고의 정체 — 세 가지가 서로 다릅니다

경고를 없애려면 어떤 경고인지 먼저 구분해야 합니다.

| 화면에 나오는 말 | 정체 | 근본 해결 |
|---|---|---|
| "Windows에서 PC를 보호했습니다" / "알 수 없는 발행자" | **SmartScreen + 서명 없음** | 코드 서명 인증서 |
| "이 파일을 열겠습니까?" (속성에 *차단 해제* 단추) | **MOTW**(인터넷에서 내려받은 표시) | 서명 + 내려받기 경로 바꾸기 |
| 백신이 격리·삭제 | **PyInstaller 오탐** | 서명 + 폴더 형태 + 오탐 신고 |

이 프로그램에서 이미 해 둔 조치(오탐·경고를 줄이는 쪽):

- UPX 압축 **끔** — 압축된 실행 파일이 오탐의 가장 큰 원인입니다.
- 버전·제조사 정보 심음(`version_info.txt`) — 속성창이 비어 있으면 평판이 더 나쁩니다.
- 아이콘 심음(`assets/hwpkit.ico`).
- 관리자 권한 요구하지 않음(`asInvoker`) — 실행할 때 권한 상승 창이 뜨지 않습니다.
- 쓰지 않는 큰 묶음(numpy·pandas 등) 제외 — 파일이 작아지고 검사도 빨라집니다.

## 3. 경고를 확실히 없애는 방법: 코드 서명

**서명 없이 경고를 완전히 없애는 방법은 없습니다.** 이것은 프로그램을 어떻게 만드느냐의
문제가 아니라, 윈도우가 "누가 만든 파일인지 증명되었는가" 를 보기 때문입니다.

```
1) 기관·회사에 이미 있는 코드 서명 인증서를 확인합니다.
   (전자세금계산서·전자문서용 인증서와는 다릅니다. "코드 서명(Code Signing)" 용도여야 합니다)
2) 없으면 발급받습니다. 국내는 한국전자인증·KICA·Sectigo 총판 등에서 취급합니다.
   · OV(조직 확인) — 값이 싸지만, 처음 며칠은 SmartScreen 평판이 쌓일 때까지 안내가 뜹니다.
   · EV(확장 검증) — USB 토큰/HSM 방식이며, 처음부터 SmartScreen 경고가 뜨지 않습니다.
3) Windows SDK 의 Signing Tools 를 설치합니다. (signtool.exe)
4) 서명합니다.

   set HWPKIT_PFX=C:\경로\인증서.pfx
   set HWPKIT_PFX_PW=암호
   sign_win.bat "dist\한글문서도우미.exe"

   USB 토큰·저장소 인증서라면:
   set HWPKIT_CERT_NAME=인증서 발행 대상 이름 일부
   sign_win.bat "dist\한글문서도우미.exe"
```

`sign_win.bat` 은 SHA256 서명 + **시간 도장(RFC3161)** 까지 넣습니다. 시간 도장이 없으면
인증서가 만료되는 순간 기존 배포본의 서명도 무효가 됩니다.

서명 뒤에는 `signtool verify /pa /v` 결과가 함께 표시되니, `Successfully verified` 가
나오는지 확인하세요.

## 4. 인증서 없이 배포할 때 (현실적인 대안)

인증서 없이도 **사내 배포**라면 경고를 사실상 없앨 수 있습니다. 핵심은
"인터넷에서 내려받았다는 표시(MOTW)를 붙이지 않는 경로로 나눠주기" 입니다.

1. **사내 공유 폴더·업무망 파일서버로 배포** — 신뢰할 수 있는 위치로 등록된 경로라면
   MOTW 가 붙지 않아 "차단 해제" 안내가 뜨지 않습니다. 메일 첨부·웹하드·메신저 전송이
   가장 나쁜 경로입니다(항상 MOTW 가 붙습니다).
2. 이미 붙은 표시를 지우려면 받는 사람이 한 번만 하면 됩니다.
   - 파일 우클릭 → 속성 → 아래쪽 **[차단 해제]** 체크 → 확인
   - 또는 PowerShell: `Unblock-File .\한글문서도우미.exe`
3. **정보보안 담당자에게 예외 등록 요청** — 가장 확실한 방법입니다. 요청할 때
   파일 해시를 함께 주면 처리가 빠릅니다.
   ```powershell
   Get-FileHash .\한글문서도우미.exe -Algorithm SHA256
   ```
   Defender 예외(해시 기준), AppLocker/WDAC 허용 규칙, 백신 정책 예외 중
   기관에서 쓰는 방식으로 등록하면 모든 PC 에서 경고가 사라집니다.
4. **백신 오탐이면 신고** — 무료이고 보통 하루 안에 반영됩니다.
   - Microsoft Defender: https://www.microsoft.com/en-us/wdsi/filesubmission
   - 국내 백신(알약·V3 등)은 각 사 오진 신고 창구를 이용하세요.
   신고가 반영되면 그 이후 배포본부터는 격리되지 않습니다.
5. **폴더 형태로 배포** — 위 1~4 를 하기 어려우면 폴더 형태가 오탐 확률이 가장 낮습니다.
   `build_win_folder.bat`(윈도우) 또는 `HWPKIT_ONEDIR=1 bash build_wine.sh`(리눅스)로
   만들면 됩니다. zip 으로 묶어 공유 폴더에 두고, **압축을 풀어서**
   `한글문서도우미.exe` 를 실행하게 하세요(zip 안에서 바로 실행하면 안 됩니다).

> 정리하면, **경고를 "없애는" 방법은 코드 서명뿐**이고, 인증서를 준비하기 전까지는
> 위 2~4번(차단 해제·예외 등록·오탐 신고)이 실무에서 쓰는 우회책입니다. 인증서 없이
> 경고가 안 뜨게 만드는 기술적 방법은 존재하지 않습니다 — 그런 방법이 있다면 그건
> 곧 악성코드가 쓰는 방법이 됩니다.

## 5. 배포 전 점검표

- [ ] `build_win.bat` 이 끝까지 성공(시험 448개 통과 포함)
- [ ] `dist\한글문서도우미.exe` 속성창에 제품 이름·버전이 보이는지
- [ ] 한/글을 켠 상태에서 실행 → `도구 → 한/글 연결 상태 보기` 가 버전을 표시하는지
- [ ] 한/글이 꺼진 상태에서 실행 → 창이 **바로 뜨고** 상태줄이
      "한/글이 켜져 있지 않습니다" 를 보이는지 (프로그램을 켜기만 해서는 한/글을
      띄우지 않습니다. 기능을 실행할 때 띄웁니다)
- [ ] 한/글이 꺼진 상태에서 아무 기능이나 실행 → 한/글이 새로 떠서 연결되는지
- [ ] 실행 중에도 창이 움직이고 `✕` 로 닫히는지
- [ ] 서명했다면 `signtool verify /pa /v` 가 `Successfully verified` 를 내는지
- [ ] 배포 경로가 공유 폴더인지(메일 첨부는 피하기)
- [ ] 필요하면 정보보안 담당자에게 해시 전달 후 예외 등록

## 6. 사내 여러 PC 에 자동 배포할 때

`version_info.txt` 의 `CompanyName`·`LegalCopyright` 를 기관 이름으로 먼저 바꾸세요.
그 다음은 기관에서 쓰는 배포 도구에 맞추면 됩니다.

- **그룹 정책(GPO) 로그온 스크립트**: 공유 폴더의 폴더 형태 빌드를 각 PC 로 복사
- **SCCM/Intune**: 폴더 형태를 앱으로 등록(설치 명령은 복사, 탐지는 exe 존재 여부)
- **간단하게**: 공유 폴더에 두고 바로 가기만 배포 (실행할 때마다 최신본이 뜹니다)

프로그램은 설정을 `%USERPROFILE%\.hwpkit\` 에만 쓰므로 관리자 권한이 필요 없고,
사용자별 양식·작업 묶음이 서로 섞이지 않습니다.
